## 故障、专项与修复

- Wry Windows 忽略 main-frame-only 标记，且独立向子 frame 注入 `window.ipc`。固定版本 vendored patch 同时约束 Tauri 初始化和 Wry 包装；显式 all-frame 初始化语义保留。真实 HTML/Markdown 的无桥断言不降低，补丁说明和原始许可证见 `src-tauri/vendor/wry/PATCH.md`。
- 目录枚举缓存的 NTFS 目录时间戳可能与操作前实时 metadata 不同，产生假冲突。目录 revision 统一取实时 metadata；普通文件保留批量枚举快路径。新增无等待修改子项后立即移动测试；100k 首层 172.424ms/300ms 的最终复核通过。
- 全量 Web 首轮出现异步对话框关闭/iframe 图片加载时序失败，增加明确就绪断言后 102 项全部通过；未增加生产 2 秒预算或测试重试。
- PDF Release service 在真正耗尽的 16MiB WSL tmpfs 写入 2MiB，失败后原目标字节不变，journal 与未完成侧文件保留。日志 `.artifacts/T311/logs/pdf-full-volume-r3.log`。WSL 9P 对 ENOSPC 返回通用 I/O 错误，这不等于 NTFS 的 ERROR_DISK_FULL 映射证明。
- 直接 Cargo Release 集成会重链 app 且可能使用 devUrl；曾与桌面运行冲突，产生拒绝访问及错误入口。专项必须先于 `pnpm build` 和桌面验收，脚本已加入运行前检查。失败和中断记录全部保留，不计通过。
- 最终完整桌面首轮仅 `external` 在覆盖后立即读取时遇到 Windows 短时 `EBUSY`。测试现在只对 `EBUSY/EPERM` 在既有轮询内重试，最终仍断言精确字节，“未修改”状态和失败日志均保留；随后完整 19/19 通过。
