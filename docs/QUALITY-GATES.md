# 质量关卡与验收策略

以下为验收策略和目标；实际已通过范围以 [PROGRESS](../tasks/PROGRESS.md) 及阶段验收记录为准。当前M0/G0、M1/G1、M2/G2已通过（2026-11-03），G2的29项feature ID与专项证据见 [M2验收](acceptance/M2.md)。G3–G5尚未通过；下一项T301/M3等待用户确认。未附证据的后续指标仍不得视为已验证。计划见 [plan](../tasks/plan.md)。

## 1. 验收证据格式

2026-11-03用户修订：**验收以 M 为单位，一个 M 只统一验收一次**。完整功能范围、数据安全要求、断言与性能预算保持不变；变化的是检查时机，优先于旧文档中逐切片或逐任务全套执行的例子。

| 时机 | 必须验证 | 构建/原生范围 | 记录 |
|---|---|---|---|
| 单个T实现完成 | 受影响模块能编译/通过类型检查，加至少一个证明新行为的定向用例；失败先修复 | 不构建Release、不跑综合桌面、不做专项 | PROGRESS 2–5行：改动、命令/exit code、留给M的待验点 |
| 高风险T（保存、删除、恢复、编码转换、跨文件替换、预览安全） | 上一条，加一条真实路径冒烟并核对字节 | 不做故障矩阵；完整故障留M验收 | 一行真实范围与结果 |
| M内全部T完成 | 任务清单的“M统一验收清单”全项，加该阶段专项 | 全量静态/单元、Web回归、Release构建、`test:desktop:all` | `docs/acceptance/<M>.md` 阶段报告 |

同一代码/构建的有效证据直接复用，只有相关改动、失败或未解决问题才扩大复测。大文件、100k目录、满盘、强杀和性能按专项选择，不随普通UI改动重跑。`scripts/check.ps1`用于明确要求的整体检查，不是日常入口。原生测试按能力选择；具体命令见任务清单的“M统一验收清单”。

不删除测试、不降低断言或性能门槛、不把未跑/待验标为通过。历史测试产物不自动清理，仍只列清理清单；新运行使用独立证据目录，避免测试框架清空上次结果。

M阶段报告记录：feature/task ID、代码版本或本地构建标识、日期、Windows/WebView2版本、fixture、输入步骤、预期、实际、命令和exit code、证据相对路径、自动/人工、mock/真实磁盘。截图不能单独证明落盘正确；应同时记录文件字节/哈希与恢复步骤。不存在的脚本、跳过的测试、未启动的应用不能写通过。

建议未来目录：`docs/acceptance/M0.md` 至 `M5.md`、`.artifacts/<build-id>/`。只有不含真实用户正文的可复现fixtures和汇总证据进入Git。

## 2. 测试分层

| 层级 | 负责什么 | 不负责什么 |
|---|---|---|
| TS unit | 命令启用态、标签/组、迟到版本处理、文本工具、源映射、设置优先级 | 真实磁盘替换、WebView2安全配置 |
| React component | 键盘、焦点、脏关闭、空/错/只读状态、设置 | 原生对话框、OS文件关联 |
| Rust unit | 编码与换行、路径/grant、regex解析、revision、恢复schema | OS极端故障的完整复现 |
| Rust integration (Windows) | 原文件保存、权限锁定、链接、监听、恢复、替换备份 | 用户是否能理解交互 |
| Web E2E | 主操作流程、可访问性、布局、bridge参数 | 产品可运行、原生IO正确；mock不越级 |
| Desktop E2E / manual | 实际Tauri/WebView2、原生对话框、系统集成、恢复与发行包 | 不能以人工一次成功代替所有回归 |
| 故障与性能 | 强杀、磁盘满、取消/超时、目标负载 | 不允许用开发模式数字代替Release |

覆盖率用于发现漏测，不设一个虚假的100%指标；高风险路径必须有有效自动化和原生演练。所有修复回归用最小能抓住行为差异的测试，不写只镜像实现的测试。

## 3. Fixtures

- 文本：空文件、单行/末尾无换行、混合LF/CRLF/孤立CR、超长单行、emoji/代理对/组合字符、中文、Tab、NUL、合法UTF16。
- 编码：UTF8±BOM、UTF16LE/BE、GBK、GB18030扩展字符、Shift_JIS、Big5、Windows1252；每种有原始字节golden、strict decode、无编辑save round-trip、有损输入反例。
- 路径：中文/空格、>260字符、大小写别名、硬链接、符号链接、junction循环、根外目标、保留设备名、尾空格点、UNC/网络断开。需要权限的fixture由隔离目录测试准备，不改用户文档权限。
- 大小：2MiB±1、20MiB±1、100MiB±1；100k项目录；搜索10k文件/100MiB文本、10k命中与50MiB结果限额。
- 内容：Java、MD、JSON/JSONC、XML、HTML/CSS/JS/TS、SQL三方言、YAML注释/锚点/多文档；JSON/XML解析错误；恶意HTML/URL/SVG和XML外部实体。
- 恢复：正常/坏校验/缺正文/旧schema/未来schema/半写清单、两个窗口session、磁盘内容变化、恢复容量满。
- 图片：小图、损坏头、超40MP/20MiB、带脚本和外部资源SVG、动画GIF。

所有生成性fixtures通过脚本创建在项目临时目录，删除前验证绝对路径在专用测试根，禁止复用用户真实路径做故障注入。

## 4. G1 MVP人工冒烟（真实Windows桌面）

1. 断网，从Release exe启动；新建无标题输入中文/emoji，CtrlS取消后内容仍在，再保存为中文带空格路径。
2. 打开fixture文件夹，展开两级目录；单击文件进入预览，编辑后固定。打开Java/JSON/SQL/XML/HTML/TXT，切回内容和undo仍在。
3. CtrlF/CtrlH搜索替换，非法正则有说明，替换全部一次undo，CtrlS字节核对。
4. 保存前后用外部程序修改同文件；clean重载提示，dirty保留两份不覆盖。另存保留内存输入。
5. 保存时继续输入，新输入仍dirty；只读/锁定/磁盘满保存失败不会显示成功。
6. 明确关闭脏标签：保存/放弃/取消分别验证。保存失败不关闭；放弃后重启不恢复已放弃内容。
7. 创建两个dirty和一个无标题，正常热退出后恢复；再做受控强杀，核对最近成功快照，记录可能丢失的最后输入窗口。
8. ≥20MiB文本只读、>100MiB仅显式前1MiB预览，不能保存截断内容；UTF16不被误判binary。
9. 全键盘Tab/Escape/CtrlP/CtrlShiftP操作，设置主题字号，125/150/200%缩放不遮挡主要按钮，重启保留。

## 5. 后续阶段必测

### G2：效率与批量操作

- 多根移除不删文件、不关闭dirty；内部跨卷拖放逐项报告。
- 同文档双组共享buffer/undo，选区/滚动独立；批量关闭中途取消能停止。
- 各编码和混合换行round-trip；转换可undo，有损确认不绕过。
- 目录搜索语法与文件内一致；取消后≤250ms停止结果投递，旧request结果不污染新搜索；达到结果/内存预算明确截断。
- 批量替换未确认零写入；脏buffer/编码风险可见；提交前外部改动停止；中途强杀能识别已完成项；回滚遇后续修改不覆盖。

### G3：阅读、格式化与导出

- Markdown所有GFM结构、相对图片、重复标题、任务准确映射；切模式不改源码。
- 预览中脚本、危险协议、SVG/远程图不执行、不自动联网、不读未授权目录。
- 渲染/格式任务过期或取消不覆盖新文本；格式化一次undo；XML外部实体不加载；SQL方言明确；YAML不丢注释锚点。
- 导出HTML断网打开仍可阅读；真实PDF打开多页/中文/图片/表格，纸张边距可变，取消/覆盖/写入失败正确。
- 图片解码和diff超限降级不OOM，SVG无应用IPC。

### G4：系统与发行

- 不依赖开发机源码/PATH/dev server，安装包与便携包均可编辑恢复。
- CLI中文路径、参数引用、--goto、--wait与窗口复用验证；进程单实例、多窗口同文件写所有权。
- 右键/关联默认不注册，opt-in后可撤销，只改自己项目项；用户后续改默认应用不会被卸载器错误覆盖。
- 便携data真实可迁移，只读位置提示；卸载不删用户文档，用户数据清理需选择。
- 缺WebView2环境给离线指引，不静默联网；无签名证书时明确未签名内部版。

### G5：完整性和故障

全部86项功能ID都关联证据。Windows11为开发机基准，Windows10真实目标验证；没有目标机器要如实标未验证，不能凭Tauri跨平台宣传当通过。保留未完成项时不宣称完整v1。

## 6. 性能方法与统一基准

[产品方案](PRODUCT.md) 给用户目标；[技术栈](TECH-STACK.md) 给实现预算。本文件规范测量方法：

- 开发基准：已核查的i5-12600KF/约32GB/Win11/SSD，用于追踪回归；目标低配：4核/8GB/SSD、Win10/11，待取得设备或受控环境验证。两者结果分别记录，不能混用。
- 每项至少10个样本，报告p50/p95/最大值；采用nearest-rank `ceil(0.95*n)`。冷启动单列，说明是否清理系统文件缓存；不得把首次用户数据为空等同OS冷缓存。
- 启动计时：CreateProcess至编辑区真实可接收输入；不是白窗出现。热启动P95≤800ms，冷/未预热≤1.5s，均为目标。
- 内存：主进程与所属WebView2子进程**私有工作集总和**，稳定30秒采样；目标≤180MiB；同时记录CPU≤1%均值。不要只截主exe数值。
- 1MiB文件打开P95≤300ms；常规输入到绘制P95≤50ms，中文IME单独检查。
- 100k文件目录首层可用目标≤300ms；只展开必要节点。只读大文件首屏≤1s目标。
- 固定10k文件/约100MiB内容搜索：首批≤500ms，总时长目标≤5s；取消≤250ms。CPU/磁盘/忽略配置完整记录。
- 100KiB Markdown更新至预览稳定目标≤300ms（包含debounce）；大文档按策略关闭实时预览。
- 应用压缩包目标≤25MiB，不含系统WebView2；初始JS gzip≤500KiB，记录按需chunk。

任何性能失败都需归因和修复；不通过改数字、少统计进程或跳过最慢样本来通过验收。
