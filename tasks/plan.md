# 分阶段实现计划

状态：**M0/G0、M1/G1、M2/G2已通过（2026-11-03）；用户已确认开始M3，当前T305**。M0–M5 才构成完整 v1；M1 是可以试用的 MVP，不是最终完成。执行细目见 [任务清单](todo.md)，状态与证据见 [进度记录](PROGRESS.md)。

## 1. 实施原则与依赖

先阅读 [产品方案](../docs/PRODUCT.md)、[能力地图](../CAPABILITY-MAP.md)、[功能矩阵](../docs/FEATURE-MATRIX.md)、[技术栈](../docs/TECH-STACK.md) 与本阶段模块 SPEC，再选择第一个依赖满足的任务。UI以 [设计规范](../design/UI-DESIGN.md) 为准，HTML原型是视觉和交互参考，不作为产品代码起点。

依赖方向：file-core 基础 → workspace / editor → search-tools / markdown / desktop；app-shell 提供注入式命令和展示槽位，不反向依赖业务实现。阶段推进依赖前一阶段关卡通过，但同一阶段内部互不依赖的任务可以并行，单个文件同一时刻只有一个写入者。

每个任务按“实际可工作的纵向切片”完成：真实用户入口 → typed bridge/服务 → 状态与错误 → 最小自检。不先造大量空页面和空IPC，不把 mock 演示当完成。通常一个工作单元改动不超过约5个生产文件；预计超出就拆子任务，不机械限制测试/fixture数。功能验收按 M 统一进行，见第 8 节。

## 2. M0：环境、工程骨架与验证通路

**目标：** 从独立目录启动真正的 Windows 桌面应用，确认所选技术与本机环境能闭环。

范围：F-DESK-013、app-shell基础；暂不标记其他产品功能完成。

- 重新执行已有环境探针，复用 Node22.13.0、pnpm10.32.1、Rust/MSVC/WebView2。不安装已存在工具，不更改机器PATH。
- 建立精确依赖、pnpm/Cargo锁文件、脚本allowlist、TS strict、lint/format/test与目录结构。
- 创建Tauri窗口、品牌token、壳层布局、可访问焦点；从设计原型提取规范而非复制textarea编辑器。
- 实现typed invoke最小往返与统一错误映射，Rust读取受控测试文件；建立fixture根授权。
- 建立Web E2E与真实WebView2验证路径。验证tauri-driver/匹配driver是否可用，缺工具先查已有位置；若无法自动化，明确记录人工原生验收路径，不能把Web mock写成桌面测试通过。
- 生成第一个真正Release可执行文件并启动；确认离线启动和不依赖本机dev server。

**关卡 G0：** pnpm typecheck/lint/unit、cargo fmt/clippy/test、真实Tauri开发启动、Release启动都有证据。完整打包安装器可以到M4，但不能只有浏览器页面。检查本项目所有新增缓存与工具落点。

**回退：** 环境或WebView2不兼容时只修最小链路，先以证据评估兼容版本，不能偷偷转Electron或下载全套SDK。

## 3. M1：可日常试用的 MVP

**目标场景：** 打开一个文件夹 → 编辑几种常见文件 → 保存 → 关闭/重启继续；异常时用户知道内容是否安全。

范围：
- FILE 001–005、008–011、013–015、017–018。
- WORK 001、003–005、007。
- EDIT 001–003、008、012–013、017–018。
- SEARCH 001–003。
- DESK 001–002、010–011。

以 [功能矩阵](../docs/FEATURE-MATRIX.md) 的完整 `F-*` ID 为准。这里的缩写只用于便于浏览。

能力：单根目录树与基本文件操作、多标签基本行为、基础语法高亮、撤销/缩进、查找替换、字号换行、主题/设置、UTF8及安全识别、保存/另存、外部变更、未保存提示与恢复、二进制/大文件保护。M1出现尚未实现的编码/混合换行等情况时，**安全只读+解释**优先，不允许有损打开后覆盖原件。

**关卡 G1：**
1. 原生应用打开真实中文路径MD/Java/JSON/SQL/XML/HTML/TXT，编辑后字节内容正确。
2. CtrlS保存、失败提示、只读、外部变更冲突、保存中继续输入、重启恢复均通过。
3. 目录仅按需读取，打开大目录不先全量索引；编辑无依赖扫描的等待。
4. 至少跑完 [质量关卡](../docs/QUALITY-GATES.md) 的MVP冒烟脚本，保留录屏/截图与文件字节校验。

**用户可试用，但 loop 继续到 M2。** 可以记录体验问题并修复，不以“以后再做”删除已列入v1的功能。

**关卡 G2：** 常用操作能够全键盘完成；搜索可取消且迟到结果丢弃；跨文件替换遇到脏buffer/外部修改时不覆盖；回滚不覆盖替换后的新修改；中文输入法、多光标、撤销跨事务正确。100k文件目录首层目标和普通文件输入延迟开始记录。

**回退：** 批量替换发生不可解释的覆盖时禁用执行入口并修复，保留预览和诊断，不继续叠加格式化。

## 5. M3：Markdown 与文本工具完整化

范围：EDIT019–020；MD001–011；SEARCH010–012。

能力：Markdown源码/阅读/分屏、目录、同步滚动、GFM任务/表格/代码、相对图片和安全链接、复制导出、HTML/PDF本地导出；格式化和结构错误定位、文本转换、图片安全查看和HTML静态预览等以矩阵为准。Java只做文本编辑与高亮；不伪装为语义格式化/编译器。

**关卡 G3：**
- 原型中的主要视觉体验迁移到真实CodeMirror与真实文件读写，而不是保留设计演示提示。
- Markdown恶意HTML/SVG/URL无法执行或越权，默认不自动加载远程图片。
- 格式化可撤销、解析失败不变更、迟到结果不覆盖新输入；JSONC注释与SQL方言有fixtures。
- HTML导出离线打开一致；PDF必须在Windows生成真正有效文件并打开校验多页、图片、中文、分页，不能仅弹打印框就标完成。技术可用WindowsWebView2隔离文档打印/PrintToPdf适配，先做spike验证，再实现用户文件选择与输出错误处理。

**回退：** 未通过隔离测试的HTML预览不启用；导出失败保留用户源码与既有输出文件。

## 8. 执行与回报

**验收以 M 为单位**（2026-11-03 用户修订）：M 内按 T 顺序实现，每个 T 只做最小自检——受影响模块能编译/通过类型检查，加至少一个能证明新行为的定向用例；不跑全量套件、不构建 Release、不做专项、不写逐任务验收文档。保存、删除/回收站、恢复/热退出、编码与换行转换、跨文件替换、预览与 HTML 安全清洗这几类高风险 T 额外跑一条真实路径冒烟。

M 内全部 T 完成后，按 [任务清单](todo.md) 的“M 统一验收清单”执行一次统一验收：全量静态与单元、Web 回归、Release 构建与 `test:desktop:all`、该阶段专项、矩阵证据汇总、`validate-docs`；写 `docs/acceptance/<M>.md`，通过才推进下一阶段。同一代码/构建的有效证据直接复用，待验项不能提前标通过。

自动loop每轮只推进一个可验证切片：读上下文 → 实现 → 自检 → 修复 → 简记 → 下一依赖就绪项。关卡通过后可直接继续下一阶段，不需反复询问授权范围内的常规实现决策。仅凭新会话没有历史不能从头重建项目。

建议首次停下来让用户体验的位置是G1和G3，但这是反馈点，不是必需的人工审批阻塞。用户要求持续loop时可继续推进并保留可体验产物。真正缺少授权的破坏性/外部发布动作、无法满足E盘安装限制等情形应写清具体阻塞。
