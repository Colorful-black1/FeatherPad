# 轻羽 FeatherPad · 编辑器 UI 设计规范

## 2026-11-04 实际使用反馈：顶部菜单与紧凑工作区

用户要求参考 VS Code 的操作组织。生产界面保留暖灰/苔绿主题与现有编辑能力，改为顶部「文件 / 编辑 / 选择 / 视图 / 转到 / 工具」菜单：从同一命令注册表读取名称、有效快捷键、禁用原因并执行；新建、打开、保存保留紧凑图标入口，命令面板常驻。缩进、语言、括号行为和编码换行统一在顶部「文档选项」展开，不再常驻横向长工具栏。工作区文件打开/保存与添加根从「文件」菜单进入，根切换/排序/移除留在工作区管理分区。

主区顺序为标签栏、只读路径导航、必要的查找/冲突/保存反馈与原 CodeMirror 编辑区；批量标签操作、导航和文本工具进入相应菜单。文件树优先占据侧栏，工作区管理、最近、收藏默认折叠，恢复与隐私入口移入侧栏；折叠不会清空记录、撤销授权或关闭文档。错误和数据保护失败继续明确提示。

菜单支持方向键、Home/End、Enter、Escape、Tab 和点击外部关闭；命令执行前恢复编辑焦点，保留选区和撤销。F6 区域导航包含新的菜单与侧栏 summary 控件。「文档选项」修改时焦点保留在选项面板，避免编辑器重配置抢走焦点。800×560 有效视口与 Web 200% 缩放需检查布局；Web 检查不能替代真实 Windows DPI 验收。下文原型尺寸和布局作为历史设计参考，以本节生产调整为准。

## 1. 产品与体验原则

轻羽 FeatherPad 面向日常文本、代码片段与 Markdown 编辑。优先让用户迅速打开、快速定位、安静书写。主屏是可编辑文档，不是卡片仪表盘；常用动作有稳定位置，低频动作收入菜单或命令面板。正式产品的 Markdown 默认进入**源码模式**，用户可主动切换阅读或分屏；本原型为展示 Markdown 特色，首次进入就打开真实中文项目文档与 config.json 标签，并采用**源码 + 阅读预览分栏**。这是展示初始状态，不覆盖正式默认值。最终工程根目录约定为 `E:\Codeing\ai-workspace\featherpad`，由父代理统一重命名，原型内部只使用相对资源路径。

品牌使用“轻羽 FeatherPad”，标识为沿对角线展开的细线羽毛，使用内联 SVG。中文名用于产品与窗口标题，英文名用于标识、工程名和辅助标签。暖灰承载界面，深墨承载内容，苔绿只用于选中、焦点、主要操作与安全状态。边界使用细线，小圆角；阴影只出现在浮层、弹窗和窄屏侧栏。

当前交付不构建真正编辑器、不引入 package、不依赖 CDN。页面使用本机系统字体、本地样式文件和 HTML 内联 SVG。所有 JavaScript 内联，双击即可使用。

| 侧栏头 | 高 44 | 高 44 | 模块名、新建、收起 |

| Breadcrumbs | 高 36 | 高 36 | 父目录、文件名、Markdown 视图切换 |
| Pane caption | 高 32 | 高 32 | 源码 / 阅读预览及同步状态 |

编辑区始终占满剩余空间。源码左侧行号区 48px；正文使用等宽字体与 1.85 行高。预览正文最大宽度 760px，常态左右内边距 40px；大于 1600 宽时 56px，小于 1100 宽时 24px。预览区使用白色或深色表面，略高于源码的明度以建立阅读分区。

标题栏右侧的最小化、最大化和关闭按钮是明确的视觉演示。点击只显示说明 toast，不操作浏览器或假装原生窗口。正式 Windows 桌面壳应由平台实现拖动区、双击最大化和系统菜单，并排除所有交互元素的拖动命中。

### 响应范围与 Windows 缩放

这是桌面效率软件，支持的最低**有效视口**是 800 × 560 CSS px。320px 手机宽度不在本产品适配范围，不提供压缩后的伪移动界面。

| 有效视口宽度 | 布局 |
| --- | --- |
| 800–1099 | 侧栏作为覆盖层打开，带遮罩；选择文件或 Esc 收起。主编辑区仍可分栏，可切单栏阅读 / 源码 |
| 1024 | 默认初次加载收起侧栏，正文内边距减至 24，保留活动栏与状态栏 |
| 1100–1279 | 固定侧栏；如阅读空间不足，用户可收起侧栏或切视图 |
| 1280 | 固定 232 侧栏，常规双栏，中文文档无需长水平滚动 |
| 1440 | 基准布局，目录、双栏与状态均完整 |
| 1920 | 增加正文留白，预览不无限拉宽；编辑内容优先，不堆叠额外面板 |

Windows 125% / 150% / 200% 缩放按 OS 的 DIP/CSS px 计算有效视口；不叠加 CSS transform 或额外 scale。以 1920 × 1080 物理分辨率为例：125% 约为 1536 × 864，有固定侧栏；150% 约为 1280 × 720；200% 约为 960 × 540，宽度使用覆盖侧栏，但高度低于最低 560，正式桌面窗口必须提示最小工作区限制或允许系统层滚动，不能声称全部可见。2560 × 1440 在 200% 为 1280 × 720，完整支持。

原型使用 min-width: 800 / min-height: 560。浏览器有效区域低于下限会裁切，用户需放大窗口或降低浏览器缩放；正式版应将 minimum window size 结合 DPI 换算到平台窗口约束。DPR 仿真只能检验像素渲染，不能替代真实 Windows 缩放与辅助技术验收。

图标用 18px 线性 SVG，工具栏小图标 13–16px，1.6px 描边。只有图标的按钮均有 aria-label 与原生 title。图标不从网络加载，不以 emoji 替代图形系统。

### 快捷键冲突策略

1. 正式桌面版由单一 command registry 分发动作；UI 按钮、菜单与快捷键使用同一 action id，显示相同的 enabled 状态。
2. 默认 Windows：Ctrl+N / O / S / W / P，Ctrl+Shift+P / F / E，Ctrl+B，Ctrl+,。原生文本编辑保留 Ctrl+Z / Y / A / C / X / V，组合输入期间不抢占事件，不覆盖输入法候选键。
3. 浏览器原型尽量拦截已定义快捷键，但 Ctrl+N / W 等可能被浏览器或 OS 优先处理；浏览器未投递的键无法保证拦截。演示时可使用同名菜单和按钮，不声称已实现系统级绑定。Ctrl+P / Ctrl+S 成功捕获后阻止打印 / 页面保存。
4. 模态开启时只处理该模态输入、方向键、Tab 与 Esc，背景编辑命令不执行。系统级 Alt+F4、Win 组合、Ctrl+Alt+Delete 保留给系统。正式版允许重映射并提示冲突，冲突配置不得静默覆盖。
5. 原型 Tab 在源码插入 2 空格（Java 为 4）；Shift+Tab 离开源码继续导航。正式版使用编辑器的“Tab 移动焦点”模式，并在状态栏显式呈现，提供 Ctrl+M 切换；缩进反缩进须经过键盘可访问性验收。

## 5. 文档、标签和导航规则

- 单击目录项打开预览标签，名称斜体；新的预览替换旧的干净预览。双击目录 / 标签固定，编辑自动固定。已打开文件再次点击只切换，不复制标签。
- 打开不同类型使用同一套 tab、breadcrumbs 和状态栏；非 Markdown 隐藏阅读视图控件，只展示源码。正式版语言模式由文件类型和用户选择共同决定。
- 未保存用实心圆点及 aria-label 表达，不能只改变文字颜色；dirty 为内容与保存基线比较，撤回到基线自动消失。关闭 dirty 标签出现“取消 / 放弃修改 / 演示保存并关闭”，默认焦点在取消。
- 关闭当前标签后激活右邻，右侧无标签则激活左邻；全部关闭后进入欢迎。原型保留同一页面内已关闭文档的最后演示保存基线，不做磁盘读取。
- 左右方向键在 tablist 中循环切换；Tab 进入当前标签，关闭按钮仍可独立聚焦。正式版补 Home / End、上下文菜单、关闭其他 / 右侧及最近关闭恢复。
- Breadcrumbs 当前展示路径层级，不提供伪造的文件系统跳转；正式版按段打开同级选择器，并与导航历史一致。
- 正式版导航包括前进 / 后退、最近文件和搜索命中位置；原型只支持文件定位与搜索结果选择区。

## 6. Markdown 阅读设计与安全

默认文档突出真实中文长文阅读：一级标题、简短介绍、引用、分节列表、表格与 JSON 代码块。源码与阅读区有独立滚动条和清楚的 pane caption，不用大卡片替代编辑器内容。

原型安全渲染仅白名单生成 h1–h3、p、br、blockquote、ul/ol/li、table/tr/th/td、pre/code、strong、hr。用户文本一律进入 textContent / Text 节点；不使用 innerHTML、eval，不执行 HTML，不创建用户提供的 URL 或图片请求。`<script>`、`<img onerror>` 与不支持的 Markdown 均为可见纯文本。少量语法能力不是完整 CommonMark 兼容承诺。

正式版 Markdown 模块应使用受控解析器并执行 HTML 清理；禁用脚本、事件属性、危险协议与自动远程加载。本地资源需通过受限资源端口，不能把系统路径直接拼成页面 URL。外链打开行为由桌面平台显式确认并显示目标。数学、图表和导出等能力按 M3 范围推进，原型无相关实现。

### PDF 导出必须输出真实文件

Markdown → PDF 是正式产品必需功能，不能以 `window.print()` 或弹出系统打印对话框作为完成标准。文件菜单与命令面板进入专用导出界面，默认文件名继承 Markdown 名称，支持 A4 / Letter 与页边距；确认后由正式导出服务实际生成 PDF 字节，并通过平台另存流程写出 `.pdf`。导出失败保留文档和设置，显示原因与重试；目标已存在遵循覆盖确认。渲染阶段有进度与取消，取消不留下损坏文件。

验收必须在离线环境生成并重新打开实际 PDF，检查中文字体嵌入或可靠替代、长段分页、标题层级、表格分页、代码块换行、链接、浅色纸张与页边距。深色编辑主题不能生成难以打印的深色纸张。输入含 HTML / 脚本时仍遵循预览安全边界；不通过远程服务上传文档。实现引擎和平台接口由 TECH 决定。

原型只提供上述导出设置的可评审 UI；“生成 PDF（未接入）”按钮禁用，不触发下载、不调用打印、不显示导出成功。真实文件生成及 PDF 验收属于 M3 / M4 交付门槛。

## 7. 状态矩阵与反馈

| 状态 | 主区呈现 | 可用动作 | 焦点 / 安全原则 | 原型覆盖 |
| --- | --- | --- | --- | --- |
| 欢迎 | 品牌、开始、最近内置文档与演示说明 | 新建、浏览样例、打开占位 | 主操作可 Tab 到达 | 可交互 |
| 空文档 | 空白源码、行 1 列 1、纯文本 | 输入、演示保存、关闭 | 新建后焦点落在源码 | 可交互 |
| 加载 | 保持壳与标签，正文短骨架，aria-busy | 取消、切换其他文档 | 不用无限 spinner，>400ms 才显示等待 | 规范，未模拟 |
| 已修改 | 标签实心点、状态栏未保存 | 演示保存、关闭确认 | 不靠颜色，关闭默认取消 | 可交互 |
| 只读 | 显示锁图标与原因，源码可选择不可编辑 | 另存为、复制、重新请求权限 | 明确文件权限 / 介质原因，不静默丢输入 | 规范，未模拟 |
| 大文件 | 顶部提示实际大小，降级能力说明 | 继续文本模式、取消 | 先显示内容，禁用重解析与高开销功能 | 规范，原型仅 20 万字符输入上限 |
| 外部变更且本地干净 | 提示已重新载入或可载入 | 撤回本次载入、查看变化 | 保留光标与滚动 | 原型只演示载入内置版本 |
| 外部变更且本地 dirty | 黄色横幅，保留当前稿 / 载入版本 / 比较 | 覆盖前二次确认 | 不自动覆盖用户修改 | 可交互，比较明确未实现 |
| 恢复会话 | 清楚说明恢复来源、时间和文件差异 | 恢复、查看、丢弃 | 先展示恢复副本，不覆盖磁盘 | 规范，未模拟 |

Toast 只承担轻量确认或说明，最多同时 3 条，6.5 秒消失，可手动关闭，使用 polite live region；不得作为真实保存失败、冲突或数据丢失风险的唯一通道。正式保存成功可只更新状态栏，失败必须持续可见。原型每次 Ctrl+S 都提示“仅内存，未写入磁盘”。

## 8. 焦点、键盘和可访问性

- 使用原生 button / input / select / textarea；目录文件为按钮，文件夹使用原生 details / summary，因此 Tab、Space / Enter 可用。未宣称实现完整 ARIA tree 的专用方向键模式。
- 页面 landmark 包括标题、主菜单、活动导航、侧栏、编辑主区和状态栏。标签使用 tablist / tab / aria-selected；设置分类使用垂直 tablist / tab / tabpanel；命令面板使用 combobox + listbox + aria-activedescendant。
- 所有图标按钮都有 aria-label 与 title；焦点可见，2px 苔绿描边；当前文件通过 aria-current 表达。dirty 标签关闭按钮的可访问名称包含“有未保存修改”。
- 打开设置后聚焦关闭按钮；打开命令与快速打开后聚焦搜索框；dirty 确认聚焦取消。Esc 关闭顶层浮层，取消而不提交数据。Tab / Shift+Tab 在模态内循环，关闭后返回触发元素；触发元素已不存在则回到编辑区。
- 搜索输入不抢占正文焦点；点击命中后选择对应文本并更新行列。如果 Markdown 处于阅读模式，会切回源码以显示命中。窄屏选择文件后收起覆盖侧栏。
- 命令与快速打开用上下方向键循环选择，Enter 执行，Esc 关闭；空结果不会执行陈旧选项。设置分类用上下方向键切换。
- 目录行、标签关闭按钮与表单控件遵循桌面精确指针密度，当前原型部分 24–28px 命中区不作为触屏产品承诺。未来桌面辅助模式可放大到 32–40px，不强制按移动产品布局改造。
- 真实屏幕阅读器、中文 IME、Windows 高对比 / forced-colors、200% 系统字体和 reduced-motion 仍需正式验收。原型的程序化焦点验证不等同于人工辅助技术认证。

## 9. 设置结构与主题

设置采用单个模态，左侧固定分类，右侧表单；即时生效，底部明确“仅本次页面有效”。不制造保存到系统配置的假象。

| 分类 | 本原型 | 正式版扩展 |
| --- | --- | --- |
| 外观 | 亮 / 暗主题、舒适 / 紧凑 | 跟随系统、侧栏布局、界面字体 |
| 编辑器 | 字号、自动换行 | 缩进、行号、字体连字、渲染空白、Tab 焦点模式 |
| Markdown | 默认视图、同步滚动 | 预览样式、安全资源、格式化偏好 |
| 文件与安全 | 无系统权限说明、冲突演示入口 | 默认编码 / 换行、保存策略、外部变更、恢复位置 |
| 快捷键 | 默认键位说明 | 搜索、重映射、冲突提示、恢复默认 |

深色使用偏绿黑和暖灰文字，层级通过背景差而非纯黑边界。强调色变为浅苔绿；所有阴影、语法辅助色、警告与错误随主题切换。密度不改变字号，字号不隐式改变全局布局缩放。原型不写 localStorage；刷新恢复默认。

## 10. 性能与动效

- 所有 UI 状态切换动画 ≤120ms；当前 hover / toast 为 100ms。跟随 prefers-reduced-motion，禁用非必要位移与渐变。
- 输入立即更新 textarea、dirty 与行列；Markdown 预览 100ms 合并更新。大文档正式版解析移到 worker，并使用有界增量更新；原型全量 DOM 渲染仅用于短样例。
- 滚动同步以 requestAnimationFrame 阻止双向反馈环；正式版需锁定主动滚动源，导航定位不触发往返滚动。
- 搜索只做内存纯文本、不执行正则；结果上限展示 60 条，并提示总数。正式版目录与结果虚拟化，搜索可取消、有进度、尊重忽略配置。
- 原型首次打开不请求网络，不等待字体或包安装。正式壳应先显示稳定界面，再异步组装文档，禁止在首屏用大动画或异步空白代替内容。

## 11. 模块边界与阶段对应

跨设计、TECH、计划及 AGENTS 使用统一模块名 **app-shell**：`no deps` 表示它不依赖任何业务模块；保持为布局、槽位和基础交互容器。启动 / composition 层单向组装业务模块，将文档视图、文件树、搜索、命令和设置通过显式接口交给壳。壳不直接读取文件、调用平台 API 或持有业务单例；业务模块也不反向通过 shell 查找服务，避免循环依赖。

建议 UI 分区映射：app-shell（标题 / 菜单 / rail / slot / 状态布局）、workspace（目录与工作区）、documents（标签 / dirty / 导航）、editor（文本输入与选区）、search（搜索 / 快速打开）、commands（动作注册与调度）、markdown（阅读与映射）、settings（偏好界面）、platform（真实桌面操作）。具体技术选型与依赖图由后续 TECH 定义；本原型的内存 state 与 DOM 函数不能当作未来模块 API。

| 阶段 | 名称 | UI / 体验验收重点 |
| --- | --- | --- |
| M0 | 壳 | app-shell no deps；布局、tokens、焦点、基础状态与可见入口 |
| M1 | MVP | 文本打开 / 编辑 / 真实保存、tab / dirty、编码换行与错误可恢复 |
| M2 | 效率 | 搜索替换、快速打开、命令、键位、导航与多文档效率 |
| M3 | Markdown 格式 | 安全预览、源码映射、同步滚动、格式化、真正生成 PDF 文件与离线验收 |
| M4 | 桌面 | Windows 壳、文件拖放、外部变更、系统菜单、打包发布与恢复 |

阶段是正式实现的推进语言，不代表已经实现 M0–M4。

## 12. 原型与正式实现边界

原型：浏览器原生 textarea + 内存样例 + 安全有限 Markdown + 对话框及布局交互。语法模式标签显示类型，不承诺语法高亮。行列以 JavaScript 字符串位置计算，尚不处理 grapheme cluster / 视觉列；自动换行时隐藏不准确行号。双向滚动是比例同步，非源行精确映射。没有系统权限、文件持久化、真实版本比较、自动恢复、窗口集成与代码执行。

正式实现：使用选定编辑器引擎与文档模型、命令服务、平台适配器和受限资源层；所有落盘、冲突、编码和恢复流程必须有独立实现及验收，不能仅替换 toast 文案。不能把演示“已保存”状态迁移成真实保存成功。未来实现应复用本设计的 token 和行为规则，不要求复用原型单 HTML 的内部结构。
